## ① `image` — 커스텀 이미지로 교체

```diff
- # https://downloads.apache.org/incubator/polaris/helm-chart/1.3.0-incubating/
+ # DataHub listener 포함 커스텀 이미지 (extensions/datahub-listener 가 빌드된 이미지)
  image:
-   repository: apache/polaris
+   repository: skthynix/polaris
-   tag: "1.3.0-incubating"
+   tag: "datahub-v1.3.0"
    pullPolicy: IfNotPresent
    configDir: /deployments/config
```

**의미**
- 업스트림 `apache/polaris:1.3.0-incubating` → 커스텀 빌드 `skthynix/polaris:datahub-v1.3.0`.
- 이 이미지에는 `polaris-extensions-datahub-listener` jar 가 `runtime/server/build/quarkus-app/lib/main/` 에 포함되고, Jandex CDI 인덱스에 `DataHubHttpEventListener` 가 박혀 있어야 합니다.
- 빌드 절차: `./gradlew :polaris-server:quarkusBuild` → `docker build -f runtime/server/src/main/docker/Dockerfile.jvm runtime/server/`.
- **이 이미지가 아니면 `eventListener.type=datahub-http` 가 부팅 시점에 실패** (CDI 인덱스에 listener bean 없음).

## ② `opa.enabled` — OPA 외부 PDP 활성화

```diff
  opa:
-   enabled: false
+   enabled: true
    authorization:
      type: opa
      policyUri: "http://opa.datahub-hynix.svc.cluster.local:8282/v1/data/polaris/authz"
      http:
        timeout: "PT2S"
        verifySsl: false
```

**의미**
- 원본: Polaris 내장 RBAC (`type: internal`) 으로 폴백 가능.
- 운영: OPA 외부 PDP 활성화. `policyUri` 가 실제 호출됨.
- **전제**: `datahub-hynix` 네임스페이스에 OPA 서비스 (`opa:8282`) 가 떠있어야 함. 없으면 **모든 인가 호출이 실패**.

## ③ `extraEnv` — DataHub listener 환경변수 7개 추가 (핵심 패턴)

```diff
  extraEnv:
    ...
    - name: JAVA_TOOL_OPTIONS
      value: >-
        -XX:MaxRAMPercentage=65.0
        -XX:InitialRAMPercentage=50.0
+   # DataHub listener 설정.
+   # ConfigMap (application.properties) 대신 env vars 로 주입해야 함 — SmallRye Config 의
+   # quarkus.config.mapping.validate-unknown=true (baked-in default) 가
+   # runtimeOnly extension 의 @ConfigMapping 을 file source 검증 단계에서 못 찾아서 거부함.
+   # env vars 는 다른 경로로 처리돼 정상 동작.
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_GMS_URL
+     value: "http://datahub-datahub-gms.datahub-hynix.svc.cluster.local:8080"
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_PLATFORM_INSTANCE
+     value: "polaris"
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_ENV
+     value: "PROD"
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_SYNCHRONOUS_MODE
+     value: "false"
+   # 격리 가드 (DataHubConfiguration @WithDefault 와 동일, 명시적 노출용)
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_CONNECT_TIMEOUT
+     value: "5s"
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_REQUEST_TIMEOUT
+     value: "10s"
+   - name: POLARIS_EVENT_LISTENER_DATAHUB_MAX_INFLIGHT_EMITS
+     value: "1000"
+   # DataHub 인증 token 이 필요하면 Secret 으로 주입:
+   # - name: POLARIS_EVENT_LISTENER_DATAHUB_TOKEN
+   #   valueFrom:
+   #     secretKeyRef:
+   #       name: polaris-datahub-token
+   #       key: token
```

**의미 (가장 중요한 변경)**
- DataHub listener 의 모든 세부 키 (`gms-url`, `platform-instance`, `env`, `synchronous-mode`, `connect-timeout`, `request-timeout`, `max-inflight-emits`) 를 **env vars 로 주입** 합니다.
- **`application.properties` (ConfigMap) 에 박으면 안 되는 이유**:
  - SmallRye Config 의 `quarkus.config.mapping.validate-unknown=true` (Polaris `runtime/defaults/application.properties` 의 baked-in default) 가
  - `runtimeOnly` 로 추가된 extension 의 `@ConfigMapping` (= `DataHubConfiguration`) 을 **file source 검증 단계에서 root 로 찾지 못해**
  - `SRCFG00050: does not map to any root` 에러로 부팅이 실패함.
- env vars 는 file source 와 다른 경로로 처리되므로 검증을 우회하고 정상 동작.
- 토큰 인증이 필요하면 Secret 으로 주입하는 패턴 (주석 예시) 도 추가됨.

## ④ `eventListener.type` — `persistence-in-memory-buffer` → `datahub-http`

```diff
  eventListener:
+   # 가능한 값: no-op, persistence-in-memory-buffer, aws-cloudwatch, datahub-http
+   # datahub-http 는 polaris-extensions-datahub-listener 가 빌드된 이미지에서만 동작
+   # DataHub 세부 설정 (gms-url, platform-instance 등) 은 extraEnv 의 POLARIS_EVENT_LISTENER_DATAHUB_*
+   # env vars 로 주입됨 (SmallRye Config 의 validate-unknown 이 file source 의 keys 를 거부하기 때문).
-   type: persistence-in-memory-buffer
+   type: datahub-http
    persistenceBuffer:
-     bufferTime: PT5S        # 5초 간격으로 DB flush
-     maxBufferSize: 1000     # 메모리 버퍼 최대 이벤트 수
+     bufferTime: PT5S        # type=persistence-in-memory-buffer 사용 시
+     maxBufferSize: 1000
```

**의미**
- 감사 이벤트의 destination 이 바뀜:
  - 원본: PostgreSQL `events` 테이블 (Polaris 내장 `PolarisPersistenceEventListener`).
  - 수정본: DataHub GMS 로 HTTP emit (`DataHubHttpEventListener`).
- `persistenceBuffer.*` 키는 남겨두었지만 (현재 type 에서는 unused), `persistence-in-memory-buffer` 로 되돌릴 때 그대로 쓸 수 있도록 유지.

## 변경 블록 간 의존 관계

```
①  커스텀 이미지 (skthynix/polaris:datahub-v1.3.0)
    └─ 빌드된 listener jar + Jandex CDI 인덱스 보유
       │
       ▼
④  eventListener.type=datahub-http  ← 이미지에 listener 없으면 부팅 실패
       │
       ▼
③  extraEnv 의 7개 DATAHUB_* env vars  ← ④ 가 활성일 때만 실제 소비됨
       └─ file properties 로 주입하면 validate-unknown 가드로 거부됨

②  opa.enabled=true  ← DataHub 와 독립이지만, 같은 운영 클러스터 전제 위에서 묶여 있음
```

**하나만 빠질 때 증상**
| 누락 | 결과 |
|---|---|
| ① 만 누락 (`apache/polaris` 이미지 사용) | 부팅 실패. CDI 가 `datahub-http` identifier 의 bean 을 못 찾음 |
| ③ 의 env vars 를 ConfigMap properties 로 옮김 | 부팅 실패. `SRCFG00050: does not map to any root` |
| ③ 만 누락 (env vars 미주입) | 부팅 자체는 OK. `@WithDefault` 로 `gms-url=http://localhost:8080` 가 박혀 emit 이 silent fail (or `connect refused` 로그 폭증) |
| ④ 만 누락 (type 미변경) | listener 가 비활성. ③ env vars 는 주입되지만 소비되지 않음 (silent no-op) |
| ② 만 누락 | OPA 호출 안 함. 내장 RBAC 로 폴백 — 보안 정책 차이 발생 |

## 변경 없는 블록 (참고)

다음 키들은 byte 단위 동일:

`replicaCount`, `imagePullSecrets`, `serviceAccount`, `podAnnotations`/`podLabels`/`configMapLabels`, `revisionHistoryLimit`, `podSecurityContext`, `containerSecurityContext`, `service`, `managementService`, `resources`, `autoscaling`, `topologySpreadConstraints`, `podDisruptionBudget`, `nodeSelector`/`tolerations`/`affinity`, `livenessProbe`/`readinessProbe`, `extraVolumes`/`extraVolumeMounts`/`extraInitContainers`, `tracing`, `metrics`, `serviceMonitor`, `logging`, `realmContext`, `features`, `persistence`, `fileIo`, `storage`, `authentication`, `cors`, `rateLimiter`, `tasks`, `minio`, `grafanaDashboard`.

또한 `extraEnv` 의 기존 항목들 (`QUARKUS_DATASOURCE_*`, `POLARIS_BOOTSTRAP_CREDENTIALS`, `GC_CONTAINER_OPTIONS`, `JAVA_TOOL_OPTIONS`) 은 변경 없음 — ③ 은 그 뒤에 **추가** 된 것.

## 회귀 위험 zone (1.3.x 포인트 릴리스 머지 시)

업스트림 1.3.x 차트가 다음을 바꾸면 이 4개 블록이 깨질 수 있으니 머지 직후 우선 확인:

1. `values.yaml` 의 `eventListener` 스키마 (예: `type` 키 이름, 새 type 추가로 인한 분기 충돌).
2. `extraEnv` 의 list-of-maps 스키마.
3. `image.repository`/`tag` 의 기본값 변경 (Helm `--reuse-values` 사용 시 stale 위험).
4. `opa.authorization.*` 구조 (특히 `policyUri` / `http.timeout` 키 이름).

```bash

  -n datahub-hynix benchmarks-polaris | grep -E 'POLARIS_EVENT_LISTENER_DATAHUB_|datahub-http|opa.datahub-hynix'
# 위 7개 env var, type=datahub-http, opa policyUri 가 모두 출력에 보여야 정상.
```
